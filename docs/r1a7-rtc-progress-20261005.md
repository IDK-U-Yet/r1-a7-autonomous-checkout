- 模型耗时与整块处理耗时分开记录，分别记录条件、预留、实际消费延迟。
- 相机帧龄/时间差异常先HOLD、废弃旧块，最多0.5秒重获合格观测；原250ms/150ms
  阈值不变，硬件反馈故障不自动恢复。
- 独立去噪步数、检查点及数据集选择参数，默认standard160 8K不变。
- 对比报告与人工阶段结果CSV、使用手册启动指令已加入。
- 最近一次代码验证：47项RTC专项测试通过；standard405 16K和默认8K无硬件
  preflight通过。未把preflight描述为模型操作效果验证。

## standard160 8K实验

固定四相机、16维、15Hz、H=50、EXP与overlap。具体统计来自本机运行日志；
原始日志、视频、数据集和权重留在runtime，不上传Git。

| 调整 | 观察与当前判断 |
|---|---|
| s=10→9→8，n10/β10/预取7 | 用户观察s8翻转改善；一轮报告10次成功7次，但是否全程无介入未确认。不能称统计显著提升。 |
| β=10→7→5，s8/n10/预取7 | 交接目标跳变P95为0.0838/0.0958/0.1130rad；人工观察低β效果不如10，保留β10。 |
| n=10/8/7/5，s8/β10/预取7 | 模型中位耗时约356.1/314.3/295.6/255.6ms；实际交接仍7步，人工观察质量下降。不是计算加速就等于任务收益。 |
| n8、s8、β10、预取/初始delay6 | 两轮合计2097次带前缀交接全为6步，无消费延迟超过条件延迟；主要收益是晚一周期采观测，不提高s8重规划频率。完整成功率尚无准确记录。 |

## standard405 16K当前基准

检查点：`pi05_oreo_standard405_a100_gpu3_full_b24_lr1e5_16k_01/checkpoints/016000/pretrained_model`。
匹配数据集：`r1a7_oreo_4cam_16d_standard405_train`。
固定s10、n10、预取7、初始delay7、β10、overlap、EXP。

- 普通推理长记录worker耗时P50/P95约245.0/251.6ms；最新有效RTC约369.9/383.7ms。
  控制间隔均约66.8ms。普通入口未单独测纯模型耗时，不能与RTC模型计时直接比较。
- 交接首步目标跳变P95：普通约0.0859rad，RTC约0.0946rad。普通入口有3步插值，
  RTC无该插值；普通预取5、RTC预留7，且RTC投影限位，因此不是只切换RTC的严格A/B。
- 用户观察：RTC完整成功概率略高、相同任务耗时约节省10%；目前仅是人工估计，
  没有准确配对试验、完整无介入成功计数及耗时分布，不标成确定提升。
- 夹爪回起点曾不收敛，误差1.2840；未进入READY的启动应排除操作效果统计。
- 有无RTC均存在特定商品位置的左手抓偏、右手接偏；这些位置原始示范正常。
  仍需区分视觉/策略目标偏差、执行跟踪和左手误差向右手交接传播，不能直接认定缺数据。

## 下一步

冻结16K基准，先选一个稳定失败位置与正常位置对照，核对训练/转换图像、动作时序、
闭爪前目标与反馈、商品在左手中的姿态。确认问题类型后再决定纠正数据或执行修复。
完整试验同时记录成功数、失败阶段、人工介入、重试与相机恢复；耗时比较匹配条件的
成功试验，并单独报告失败与重试。现阶段没有修改机器人控制、安全阈值或训练模型。
